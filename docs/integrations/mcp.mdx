---
title: 'MCP Bridge'
description: 'Connect AI assistants to Anima via the Model Context Protocol'
---

The MCP server wraps Anima as a set of 14 tools that any MCP-compatible assistant can call: ten memory tools (`memory_search`, `memory_add`, `memory_update`, `memory_delete`, `memory_list`, `memory_stats`, `memory_ask`, `memory_reflect`, `memory_discover`, `memory_briefing`) and four skill tools (`skill_list`, `skill_get`, `skill_save`, `skill_delete`).

<Note>
The server binary has the same tools built in: `anima-server mcp`. Use
[`anima-server connect`](/integrations/connect) to set it up; the TypeScript
bridge below is for clients that do not have the binary.
</Note>

## Setup

```bash
cd mcp
npm install
npm run build
```

## Configuration

Point your MCP client (Claude Desktop, Cursor, etc.) at the built MCP server. The MCP bridge connects to the Anima REST API, which must be running.

The bridge reads four environment variables:

| Variable | Default | Purpose |
|----------|---------|---------|
| `ANIMA_BASE_URL` | `http://127.0.0.1:3000` | Address of the Anima API (`ANIMA_URL` is read as a fallback) |
| `ANIMA_API_KEY` | empty | Sent as `Authorization: Bearer <key>` when the server requires one |
| `ANIMA_NAMESPACE` | `default` | Namespace sent in `X-Anima-Namespace` on every call |
| `ANIMA_PROJECT` | detected | Project the session works on, see [Projects](#projects) |

## Available Tools

| Tool | Description |
|------|-------------|
| `memory_search` | Hybrid search over stored memories. Results include `category`, `confidence`, and `source`. `scope`: `all` (default) searches the general memories and every project, `project` only the current project's. |
| `memory_add` | Store a new memory (optional `category`). It goes to the current project unless `scope` is `global`; `project` names the project when none is detected. The answer gives the `namespace` it was stored in. |
| `memory_update` | Update an existing memory |
| `memory_delete` | Delete a memory |
| `memory_stats` | Get memory store statistics |
| `memory_ask` | Ask a question with enriched retrieval |
| `memory_reflect` | Trigger reflection on recent memories |
| `memory_list` | List stored memories |
| `memory_discover` | Find memories matching a `positive` text concept while steering away from an optional `negative` one (`limit`, default 10) |
| `memory_briefing` | Short session briefing: profile, project memories and the skill index. `project` defaults to the current project. |
| `skill_list` | List stored skills |
| `skill_get` | Load a skill's instructions |
| `skill_save` | Create or update a skill |
| `skill_delete` | Delete a skill |

## Projects

Both `anima-server mcp` and the TypeScript bridge detect the project the session works on once, when the MCP client starts them: `ANIMA_PROJECT` when set, then the git repository of the working folder (its `origin` remote's name, else its main checkout's folder, so worktrees share one project), then the folder's name. See [Projects](/concepts/namespaces#projects).

- `memory_add` stores in `<namespace>/<project>`. With `scope: "global"` it stores in the namespace itself, for facts that hold in every project: who the user is, general preferences, ways of working.
- `memory_search` with `scope: "project"` runs in `<namespace>/<project>`; without a current project it returns an error asking for `project` or scope `all`.
- `memory_briefing` asks for the current project's briefing unless the call names another `project`.

A detected project takes precedence over the `project` argument of `memory_add` and `memory_search`, which serves when none is detected. Set `ANIMA_PROJECT` in the MCP server's environment to pin the project, for example when the client starts servers from a folder unrelated to the work.
