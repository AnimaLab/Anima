The web app provides a visual surface for memories, search results, graph relationships, embedding space, chat, skills, background processing and settings, scoped to the selected namespace.

## Setup

```bash
cd web
npm install
npm run dev
```

The dev server listens on `http://localhost:5173` and proxies `/api` and `/health` to the Anima server at `http://localhost:3000`, which must be running.

## Pages

- **Dashboard** (`/`) — what Anima remembers in the current namespace, at a glance
- **Memories** (`/memories`) — list, filter, and inspect stored memories with full metadata
- **Search** (`/search`) — run hybrid, vector, or keyword searches, or ask a question, with per-signal scores for each result
- **Skills** (`/skills`) — browse and edit the stored skills
- **Graph** (`/graph`) — memories linked by similarity
- **Embeddings** (`/graph3d`) — memories placed by meaning in a 3D view of the vector space
- **Conflicts** (`/conflicts`) — the ledger of memories that replaced or contradicted an earlier one, with what changed and why
- **Chat** (`/chat`) — conversational interface backed by memory-augmented retrieval, with saved conversations
- **Processor** (`/processor`) — log of the background jobs: reflection, deduction, reconsolidation and retention
- **Settings** (`/settings`) — namespaces (switch, rename or delete, each with the namespaces below it), server models, chat model, server profiles, search tiers, background processing, the telemetry switch, and backup and restore

The namespace selector lists sub-namespaces, such as the [project namespaces](/concepts/namespaces#projects), indented below their parent. **About Anima**, in the menu, introduces Anima in seven steps with animated illustrations.

## Model setup

When the server runs without a configuration of its own (on `config.default.toml` or the built-in defaults), the web UI opens a **Set up Anima** dialog that asks where the models run:

- **OpenAI-compatible API**: one server URL and key for every model (OpenAI, Groq, vLLM, Ollama...). The dialog lists the server's models, then asks for the chat, embedding and re-ranking models.
- **On this machine**: the built-in search models, downloaded on the first start (BGE-M3, about 2.3 GB, required to search; bge-reranker-v2-m3, about 570 MB, optional), and a chat model served by Ollama at `http://localhost:11434/v1` (default `qwen3.5:4b`, fetched with `ollama pull`).

**Start Anima** writes the choice into `config.toml` and restarts the server; the page reloads when it is back. **Later** asks again in the next browser session. **Settings > Server models** shows the same fields to change the choice afterwards, with **Save and restart**. When the embedding model changes on a store that holds memories, Settings then offers to re-index them with the new model. What is written is described in [Configuration](/configuration#setting-up-the-models-from-the-web-ui).

## Production Build

For production use, build the static assets and serve them from the Anima server:

```bash
cd web
npm run build
```

The built files in `web/dist/` are served by the Rust server at port 3000.
