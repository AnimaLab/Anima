---
title: 'Connect a harness'
description: 'Give Claude Code, Codex, Cursor, Hermes and other harnesses the same memory'
---

`anima-server connect` registers Anima with an AI harness so the model can read and write your memory. Run it once per machine; every harness you connect shares the same memories.

```bash
anima-server connect claude
anima-server connect all        # every supported harness found on this machine
```

## What it writes

| Harness | MCP server | Instructions | Automatic recall |
|---------|------------|--------------|------------------|
| `claude` (Claude Code) | `~/.claude.json` | `~/.claude/CLAUDE.md`, `~/.claude/skills/anima/` | hooks in `~/.claude/settings.json` |
| `claude-desktop` | `claude_desktop_config.json` | | |
| `codex` | `~/.codex/config.toml` | `~/.codex/AGENTS.md`, `~/.codex/skills/anima/` | |
| `cursor` | `~/.cursor/mcp.json` | | |
| `hermes` | memory provider plugin in `plugins/anima/` | `skills/anima/` | by Hermes, through the provider |

- **MCP server**: an entry named `anima` that runs `anima-server mcp`.
- **Instructions**: a block between `<!-- anima:start -->` and `<!-- anima:end -->` telling the model to search memory before a task and save durable facts.
- **The anima skill**: a `SKILL.md` with the full guide to using this memory, in the harness's own skills folder.
- **Automatic recall**: at session start the harness receives a [briefing](/concepts/briefing-and-skills): your profile, what is relevant to the working folder, and the list of stored skills. On each prompt it receives the memories that match it. If the server is unreachable the hooks print nothing and never block the harness.

Each edit keeps the rest of the file, is safe to repeat, and leaves a `.before-anima` copy of the original the first time. Restart the harness to load Anima.

## Hermes

Hermes has a slot for one external memory provider, which it calls before every model request. `connect hermes` fills it: it copies a small plugin to `$HERMES_HOME/plugins/anima/` and sets `memory.provider: anima` in `config.yaml`. Hermes keeps its home in `$HERMES_HOME`, in `%LOCALAPPDATA%\hermes` on Windows, or in `~/.hermes`.

With the provider active:

- the first turn of a session carries Anima's briefing, and every turn carries the memories matching the message;
- writes made with Hermes's built-in `memory` tool are mirrored to Anima, so other harnesses see them;
- the model gets `memory_search`, `memory_add`, `memory_update`, `memory_delete`, `skill_list`, `skill_get` and `skill_save`.

Conversation turns are not uploaded. Recall is bounded to three seconds, and a server that is down only means a turn without recalled context.

If `memory.provider` already names another provider, it is left alone and Anima is added under `mcp_servers` instead. `hermes memory status` shows which provider is active.

## Options

| Option | Effect |
|--------|--------|
| `--dry-run` | Show what would change without writing |
| `--no-hooks` | Skip the automatic recall hooks |
| `--no-instructions` | Skip the instruction block |
| `--url <url>` | Address of the Anima server (default `http://127.0.0.1:3000`) |
| `--api-key <key>` | API key, when the server requires one |
| `--namespace <name>` | Memory namespace (default `default`) |

The address, key and namespace are saved to `~/.anima/client.json` and read by `mcp`, `recall`, `export` and `import`. They are never written into the harness files. `ANIMA_BASE_URL`, `ANIMA_API_KEY` and `ANIMA_NAMESPACE` override the file.

## Other harnesses

```bash
anima-server connect print
```

prints the MCP entry and the instruction text to paste into any client that speaks MCP over stdio.

## Disconnect

```bash
anima-server disconnect claude
```

removes the MCP entry, the instruction block, the anima skill and the hooks, and leaves everything else in place.

## Move to another machine

```bash
anima-server export memories.json    # old machine
anima-server import memories.json    # new machine
anima-server connect all
```

The export is JSON with every namespace and skill, original IDs, dates, categories and confidence. It holds no embeddings, so the two machines can use different embedding models. Importing the same file twice skips what is already there.

| Command | Result |
|---------|--------|
| `export [file]` | Portable JSON, all namespaces |
| `export --only-namespace` | Only the selected namespace |
| `export --full` | SQLite snapshot, including conversations, plans and history |
| `import <file>` | Merge into the server, keeping namespaces |
| `import <file> --into-namespace` | Put everything in the selected namespace |
| `import <file> --replace` | Replace existing memories; required for a full snapshot |
