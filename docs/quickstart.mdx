## Install

Pick whichever method gets you running fastest.

<Tabs>
  <Tab title="Download binary">
    Download the archive for your platform from [GitHub Releases](https://github.com/AnimaLab/Anima/releases). No Rust toolchain needed. Archives are named `anima-server-<version>-<target>`:

    | Platform | Archive |
    |----------|---------|
    | macOS (Apple Silicon) | `anima-server-<version>-aarch64-apple-darwin.tar.gz` |
    | Linux (x86_64) | `anima-server-<version>-x86_64-unknown-linux-gnu.tar.gz` |
    | Linux (aarch64) | `anima-server-<version>-aarch64-unknown-linux-gnu.tar.gz` |
    | Windows (x86_64) | `anima-server-<version>-x86_64-pc-windows-msvc.zip` |

    ```bash
    # macOS (Apple Silicon), with <version> taken from the Releases page, e.g. v0.3.0
    VERSION=v0.3.0
    curl -L https://github.com/AnimaLab/Anima/releases/download/$VERSION/anima-server-$VERSION-aarch64-apple-darwin.tar.gz | tar xz
    cd anima-server-$VERSION-aarch64-apple-darwin && ./anima-server
    ```

    The archive holds the binary, `config.default.toml`, the built web UI (`web/dist`), the BGE-M3 sparse weights (`models/bge-m3/sparse_linear.bin`), service templates, `README.md` and `LICENSE`. Run `anima-server` from the extracted folder.
  </Tab>
  <Tab title="Docker">
    ```bash
    docker run -p 3000:3000 -e ANIMA_API_KEY=your-secret-key -v ./anima.db:/app/anima.db ghcr.io/animalab/anima:latest
    ```

    The container listens on all interfaces, so it requires an API key. Add `-H "Authorization: Bearer your-secret-key"` to every `curl` call below (or `X-Anima-Api-Key: your-secret-key` for clients that cannot set `Authorization`).
  </Tab>
  <Tab title="Build from source">
    ```bash
    cargo build --release -p anima-server
    ./target/release/anima-server
    ```
  </Tab>
</Tabs>

Anima starts on `http://localhost:3000`. On first run it downloads the local models: the BGE-M3 embedder (several GB with its weights) and the bge-reranker-v2-m3 re-ranker (571 MB). Set `enabled = false` under `[reranker]` to skip the re-ranker. The web UI is served at the same address.

## Store and Search

<Steps>
  <Step title="Store a memory">
    ```bash
    curl -X POST http://localhost:3000/api/v1/memories \
      -H "Content-Type: application/json" \
      -H "X-Anima-Namespace: default" \
      -d '{"content": "I love hiking on weekends.", "tags": ["preference"]}'
    ```
  </Step>
  <Step title="Search">
    ```bash
    curl -X POST http://localhost:3000/api/v1/memories/search \
      -H "Content-Type: application/json" \
      -H "X-Anima-Namespace: default" \
      -d '{"query": "What does the user like to do on weekends?", "limit": 5}'
    ```
  </Step>
</Steps>

Store and search work with zero configuration — no LLM needed.

You can also specify a semantic category and source:

```bash
curl -X POST http://localhost:3000/api/v1/memories \
  -H "Content-Type: application/json" \
  -H "X-Anima-Namespace: default" \
  -d '{
    "content": "I prefer dark mode in all my editors.",
    "category": "preference",
    "source": "user_stated"
  }'
```

## LLM Setup

The `/ask` and `/chat` endpoints need an LLM backend. By default Anima expects Ollama:

```bash
ollama serve
ollama pull qwen3.5:4b
```

Anima reads `config.toml` from the working directory, then falls back to `config.default.toml`; `anima-server path/to/config.toml` names another file. To change a setting, copy `config.default.toml` to `config.toml` and edit the copy. For example, to use a cloud API instead (OpenAI, Groq, Together, etc.):

```toml
[llm]
base_url = "https://api.groq.com/openai/v1"
model = "qwen/qwen3-32b"
api_key = ""  # or set OPENAI_API_KEY env var
```

<Info>
  Without an LLM, `/ask` degrades gracefully — it returns retrieval results directly with `"degraded": true` instead of failing.
</Info>

## Ask and Chat

<Steps>
  <Step title="Ask a question">
    ```bash
    curl -X POST http://localhost:3000/api/v1/ask \
      -H "Content-Type: application/json" \
      -H "X-Anima-Namespace: default" \
      -d '{"question": "What pet does the user have?"}'
    ```

    Response:
    ```json

      "answer": "The user has a golden retriever named Max.",

          "score": 0.89,

  </Step>

    ```
  </Step>
</Steps>

## Embedding Backend

By default, Anima uses a local ONNX embedding model — no API calls required. To use a cloud provider instead:

```toml
[embedding]
backend = "openai_compat"
api_base_url = "https://api.cohere.com/compatibility/v1"
api_model = "embed-v4.0"
api_key = ""  # or set EMBEDDING_API_KEY env var
dimension = 1024
```

Works with OpenAI, Cohere, Voyage, Together, vLLM, or any OpenAI-compatible endpoint.

`query_instruction` is prepended to search queries, as with the local backend.
Anima sends `dimensions` with each request; set `request_dimensions = false` for
models that reject it (such as `text-embedding-ada-002`, or a model without
Matryoshka support served by vLLM), with `dimension` set to the model's native size.

<Warning>
  Switching embedding backends on an existing database produces incompatible vectors. Start with a fresh database when changing backends.
</Warning>
