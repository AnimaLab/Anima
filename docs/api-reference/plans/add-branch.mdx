## POST /api/v1/plans/{id}/branches

A recovery branch records an alternative path taken when part of a plan goes wrong: what triggered it, where it started and how it continues. A new branch starts with status `active`, and its creation is written to the audit log.

<ParamField header="X-Anima-Namespace" type="string" required>
  Namespace of the plan
</ParamField>

<ParamField path="id" type="string" required>
  Plan ID. The plan must belong to the namespace itself (child namespaces excluded); another plan ID gives `500` with `plan <id> does not exist in namespace <namespace>`.
</ParamField>

## Request Body

<ParamField body="branch_label" type="string" required>
  Short name of the branch. Empty label gives `400`.
</ParamField>

<ParamField body="trigger_reason" type="string" required>
  Why the branch was opened. Empty reason gives `400`.
</ParamField>

<ParamField body="source_checkpoint_id" type="string">
  ID of the checkpoint the branch starts from, stored as given
</ParamField>

<ParamField body="branch_plan" type="any">
  Free-form JSON describing the alternative steps
</ParamField>

<ParamField body="metadata" type="object">
  Arbitrary metadata. Values under sensitive keys (`password`, `secret`, `token`, `auth`, ...) are stored as `"[redacted]"`.
</ParamField>

## Response

Returns the created branch.

<ResponseField name="id" type="string">
  Branch ID
</ResponseField>

<ResponseField name="namespace" type="string">
  Namespace of the branch
</ResponseField>

<ResponseField name="plan_id" type="string">
  Plan ID
</ResponseField>

<ResponseField name="source_checkpoint_id" type="string | null">
  Checkpoint the branch starts from
</ResponseField>

<ResponseField name="branch_label" type="string">
  Branch label, trimmed
</ResponseField>

<ResponseField name="trigger_reason" type="string">
  Trigger reason, trimmed
</ResponseField>

<ResponseField name="status" type="string">
  `active`, `resolved` or `abandoned`
</ResponseField>

<ResponseField name="branch_plan" type="any | null">
  Alternative steps
</ResponseField>

<ResponseField name="metadata" type="object | null">
  Branch metadata
</ResponseField>

<ResponseField name="resolution_notes" type="string | null">
  Notes recorded when the branch was resolved
</ResponseField>

<ResponseField name="created_at" type="string">
  Creation time
</ResponseField>

<ResponseField name="updated_at" type="string">
  Last update time
</ResponseField>

<ResponseField name="resolved_at" type="string | null">
  When the branch reached `resolved` or `abandoned`
</ResponseField>

## Example

```bash
curl -X POST http://localhost:3000/api/v1/plans/01JCP4Q8R2S3T4V5W6X7Y8Z9A0/branches \
  -H "Content-Type: application/json" \
  -H "X-Anima-Namespace: default" \
  -d '{
    "source_checkpoint_id": "01JCP5A1B2C3D4E5F6G7H8J9K0",
    "branch_label": "restore-from-snapshot",
    "trigger_reason": "pg_upgrade failed on a corrupted index",
    "branch_plan": {"steps": ["restore snapshot", "reindex", "retry pg_upgrade"]}
  }'
```
