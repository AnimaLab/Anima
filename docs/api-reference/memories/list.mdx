---
title: 'List Memories'
description: 'Retrieve memories with pagination and filtering'
---

## GET /api/v1/memories

<ParamField header="X-Anima-Namespace" type="string" required>
  Target namespace (its child namespaces are included)
</ParamField>

## Query Parameters

<ParamField query="offset" type="integer" default="0">
  Pagination offset
</ParamField>

<ParamField query="limit" type="integer" default="50">
  Number of memories to return, at most 200
</ParamField>

<ParamField query="status" type="string">
  Filter by memory status (e.g. `active`, `superseded`)
</ParamField>

<ParamField query="memory_type" type="string">
  Filter by memory type: `raw`, `reflected`, `deduced`, `induced`, or `merged`
</ParamField>

<ParamField query="category" type="string">
  Filter by semantic category (e.g. `preference`, `identity`, `routine`)
</ParamField>

<ParamField query="cursor" type="string">
  Cursor for keyset pagination. Pass the `next_cursor` value from a previous response to get the next page. When present, `offset` is ignored. Provides constant-time page fetches regardless of depth.
</ParamField>

## Response

Memories are ordered newest first.

<ResponseField name="memories" type="object[]">
  Memory objects, with the same fields as [Get Memory](/api-reference/memories/get)
</ResponseField>

<ResponseField name="total" type="integer">
  Number of memories matching the filters
</ResponseField>

<ResponseField name="offset" type="integer">
  Offset of this page
</ResponseField>

<ResponseField name="limit" type="integer">
  Page size applied
</ResponseField>

<ResponseField name="next_cursor" type="string">
  Cursor for the next page, present when the page is full. Absent on the last page.
</ResponseField>
