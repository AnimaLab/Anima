title: 'Processor Status'
description: 'Queue state and counters of the background processor'

## GET /api/v1/processor/status

Reports the background processor's queue and what it has done since the server started. The endpoint is server-wide and takes no namespace header. When the processor is disabled, `enabled` is `false`, `idle` is `true` and every counter is `0`, except `ingestion`.

## Response

<ResponseField name="enabled" type="boolean">
  Whether the background processor is running
</ResponseField>

<ResponseField name="queue_depth" type="integer">
  Jobs waiting to be picked up
</ResponseField>

<ResponseField name="in_flight" type="integer">
  Jobs being executed
</ResponseField>

<ResponseField name="dead_letter_count" type="integer">
  Jobs dropped because the queue was full or closed
</ResponseField>

<ResponseField name="idle" type="boolean">
  `true` when `queue_depth` and `in_flight` are both `0`
</ResponseField>

<ResponseField name="ingestion" type="object">
  Memories ingested since start: `total`, `rate_per_sec` (rounded to two decimals) and `uptime_secs`
</ResponseField>

<ResponseField name="metrics" type="object">
  Counters since start:
  - jobs: `completed_jobs`, `failed_jobs`
  - created memories: `reflected_created`, `deduced_created`
  - working-memory commits: `committed_evaluated`, `committed_written`
  - reconsolidation: `recon_processed`, `recon_superseded`
  - retention: `retention_processed`, `retention_softened`
  - LLM usage, overall (`llm_`) and per pipeline (`reflection_`, `deduction_`, `induction_`): `*_calls` (`llm_calls`, `reflection_llm_calls`, ...), `*_usage_missing` (calls whose response reported no token usage), `*_prompt_tokens`, `*_completion_tokens`, `*_total_tokens`
</ResponseField>

curl http://localhost:3000/api/v1/processor/status
